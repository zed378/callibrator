# 04 — `@callibrator/i18n` (TARGET)

> **Status: TARGET (ADR-134). Not built.** What it generalises is **as built** in
> `frontend/src/i18n/` (P10-02, P10-13, ADR-098 § 4 and Amendment 2): `config.ts` (locales `id`, `en`;
> default `id`; no Accept-Language sniffing), `translate.ts` (`createTranslator`, `pickMessages`),
> `format.ts` (`{name}` placeholders), `messages/id.ts` (the **source** dictionary, ~584 lines) and
> `messages/en.ts` (typed against it), `apiErrors.ts` (status + code → message key) and the
> `MessagesProvider`. Built by P35-04.

---

## 1. What Exists Today, Precisely

- **Two locales, Indonesian first.** `id` is the default for everyone (`DEFAULT_LOCALE = "id"`),
  chosen by a `locale` cookie, never by the browser's language.
- **Flat, namespaced keys** (`pub.*`, `landing.*`, `auth.*`, `access.*`, `verify.*`, `reset.*`,
  `invite.*`, `content.*` — 437 keys on 2026-10-08). `en.ts` is typed against `id.ts`'s key set, so a key
  missing in English is a **compile error**.
- **Placeholders only**: `format()` fills `{name}`; a missing value is left visible on purpose.
  **No plural rule exists** today.
- **Client bundles carry only their namespaces**: a server page hands a client component
  `pickMessages(messages, ["auth."])`, so neither full dictionary (~44 KB) reaches a public page's
  bundle (P10-13). The landing page is at **148.7 of 150 KB** gzip (`CLAUDE.md`, 2026-10-05) — any
  i18n change on the web is a bundle-budget change.
- **The dashboard is English-only** (ADR-098 § 4; `htmlLangFor` keeps `/dashboard` `en`): its strings
  are literals in components, not dictionary keys. The `/field` app (target, P19-08) is bilingual
  (`field.*`, `field.conflicts.*`).
- **Public pages never render the backend's English `message`**: `apiErrors.ts` maps status and
  `code` to keys (ADR-098, doc 20 § 5 item 7).
- **A guard on claims**: `copyTruthfulness.p1011.test.ts` fails the build on a banned term, an
  unsourced number, or a claim key missing from its source table.

## 2. What the Package Holds

```text
packages/i18n/
├── src/
│   ├── config.ts        # LOCALES, Locale, DEFAULT_LOCALE, isLocale, resolveLocale (moved as is)
│   ├── format.ts        # {name} placeholders + the plural subset (§ 3)
│   ├── translate.ts     # createTranslator, pickMessages (moved as is)
│   ├── formatters.ts    # Intl-based date, time, number, IDR currency, relative time (§ 4)
│   ├── apiErrors.ts     # status/code → MessageKey (moved, made transport-agnostic: reads ApiError fields)
│   └── messages/
│       ├── id.ts        # SOURCE dictionary of the SHARED namespaces (§ 5)
│       └── en.ts        # typed against id.ts
└── test/                # 100 %
```

The package exports **no React**. The providers (`MessagesProvider` on the web; the app's own context)
stay in each app; `@callibrator/hooks` adds a `useTranslate()` that reads whichever context the app
supplies through a tiny interface (`07` § 4).

## 3. The Message Syntax: `{name}` Plus a Plural Subset — Not Full ICU

**Decision (ADR-134 § A.7):** keep the as-built `{name}` syntax and add exactly one construct, the
**plural select**, implemented in the package over the built-in `Intl.PluralRules`:

```text
"field.outbox.count": "{count, plural, one {# capture waiting} other {# captures waiting}}"
"field.outbox.count" (id): "{count, plural, other {# tangkapan menunggu}}"
```

- Supported: `{name}`, `{n, plural, =0 {…} one {…} other {…}}` with `#` for the number. Nothing else —
  no `select`, no nested arguments, no number/date skeletons inside messages (formatting is done by
  `formatters.ts` before the value is passed in).
- Indonesian has a single plural category (`other`); English has `one`/`other`. A message whose
  `other` branch is missing is refused by a dictionary test.
- **Why not full ICU (`intl-messageformat`, FormatJS):** the public pages' bundle budget (148.7 of
  150 KB) cannot take its runtime; our dictionaries use one construct ICU offers; and a parser in the
  package is ~60 lines with a 100 % test. If `select` is ever needed, it is added the same way, by an
  amendment, not by importing a framework.
- **Hermes:** `Intl.PluralRules`, `NumberFormat`, `DateTimeFormat` and `RelativeTimeFormat` are
  required. P34 (the app's foundation) proves them on Hermes on both platforms for `id-ID` and `en`;
  where a platform lacks one, the app adds the matching `@formatjs/intl-*` polyfill **in the app**, never
  in the package.

## 4. Formatters

All formatting goes through the package so the web and the app print the same date the same way:

| Function | Rule |
|---|---|
| `formatDate(value, { locale, timeZone })` | **the tenant's time zone** (the IPM/calibration "day" is the tenant's local day — UD-7, ADR-126; `tenantSettings.timeZone` reaches the offline client in the working set, P19-08 § 7.1), never the device's; `id`: `8 Okt 2026`, `en`: `8 Oct 2026` |
| `formatDateTime` | as above, 24-hour clock in both locales |
| `formatNumber`, `formatDecimal(value, { fractionDigits })` | measured values keep their stated precision; **decimals arrive as strings** from the API (as built, `docs/API/14` § 4.5) and are formatted without passing through a float where the precision matters |
| `formatCurrency(value, "IDR")` | `Rp 1.500.000` (`id`), `IDR 1,500,000` (`en`) |
| `formatRelative(value, now)` | "3 hari lalu" / "3 days ago" — for "last synced", never for a regulated date, which is always absolute |

## 5. Dictionaries — Which Keys Live Where

**Rule:** a key used by **more than one platform** lives in the package; a key used by **one
platform** stays in that app. Both sides keep the `id`-is-source, `en`-is-typed rule, and both use
`pickMessages` so a client bundle carries only what it renders.

| Namespace | Home | Notes |
|---|---|---|
| `common.*` (OK, Cancel, Retry, Sign in, Offline, Last synced …) | package | new |
| `errors.*` — `errors.http.<status>`, `errors.conflict.<CODE>`, `errors.network`, `errors.timeout`, `errors.rateLimited` | package | the conflict codes are the tuples in contracts (`IPM_CONFLICT_CODES`, `IDEMPOTENCY_CONFLICT_CODES`, the device codes of P19-03, `SCOPE_LOSS_CODES`); a test fails if a code has no message in both locales |
| `status.<domain>.<state>` — every label of the status registry | package | **new keys**: the registry's labels are English literals today (`statusTone.ts`). The web dashboard keeps showing the English words (it is English-only, ADR-098 § 4) by reading the `en` dictionary; the app shows `id` by default. No dashboard copy changes |
| `field.*`, `field.conflicts.*` | package | the PWA and the app share the capture vocabulary and the conflict explanations (P19-08 § 9.6) |
| `auth.*` | package | sign-in, MFA, passkey, SSO wording shared by both sign-in screens |
| `verify.*` | package | the QR verification result wording — the app's auditor flow shows the same verdicts as `/verify` |
| `pub.*`, `landing.*`, `access.*`, `content.*`, `invite.*`, `reset.*` | **web** (`frontend/src/i18n/messages/`) | public marketing and account pages; the claim guard (`copyTruthfulness.p1011`) stays with them |
| app-only screens (`mobile.*`) | **app** | `../MOBILE/10` |

Moving `auth.*` and `verify.*` changes no string: the move is proved by comparing the merged web
dictionary before and after, key by key and value by value (P35-04 DoD).

## 6. Migration of the Web's i18n (target, P35-04)

1. Move `config.ts`, `format.ts`, `translate.ts` into the package **unchanged** (same exports); the
   web's `src/i18n/index.ts` re-exports them so no import in `frontend/` changes in this step.
2. Move `apiErrors.ts`'s mapping table; the web keeps a thin `readApiFailure` that turns an axios error
   into the package's `ApiError` fields (until P35-11).
3. Split the dictionaries per § 5: shared namespaces to the package, the rest stay. The web's
   `getMessages(locale)` returns the **merge** of the package's and its own, typed as one `Messages`.
4. Add the plural construct and the formatters; adopt them in the web only where a screen changes for
   another reason (no sweep).
5. Gates: `i18n.p1002.test.ts`, `copyTruthfulness.p1011.test.ts` green and unchanged in case names and
   count; the `next build` bundle budget (10/10 within; `/` ≤ 150 KB gzip) held — measured, not assumed.

## 7. Bad Implications

- Two dictionary homes per locale (package + app). Mitigated by the one-sentence rule of § 5 and by
  a test that fails when the same key exists in both.
- The status labels gain Indonesian before the dashboard does; until the owner decides the
  dashboard's language, the web reads the `en` copy of keys the app reads in `id`.
- No full ICU: a translator used to ICU `select` must ask for an amendment.
