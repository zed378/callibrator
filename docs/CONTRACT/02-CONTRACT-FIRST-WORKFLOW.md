# 02 — The Contract-First Workflow (TARGET)

> **TARGET — nothing here is built.** Decision: ADR-136, which supersedes ADR-103's code-first rule
> and keeps its gates. As built today (ADR-103): each route module has a sibling `<name>.openapi.ts`
> naming the Zod schema its `validate()` mounts; `npm run openapi:generate` writes
> `backend/openapi.json`; `openapi:check` / `openapi:lint` (Spectral) / `openapi:breaking` (oasdiff)
> and the route-without-doc guard `openapiRoutes.p925` gate it; the frontend generates types with
> `openapi-typescript` (`npm run api:types`, `api:types:check`).

---

## 1. The Loop

```
1. edit contracts/            the operation, its schemas, its error codes, any named rule + vectors
2. contract gates             lint · breaking (v1 is additive only) · codes registry · vectors schema
3. generate                   Node: Zod + types into backend/src/generated/contract/ (§ 3)
                              clients: packages/api-client types; i18n code keys; mobile = same package
                              Go/other: their generators (P34 / Phase 999)
4. implement                  each backend that serves the module implements the operation
5. conform                    the conformance suite (06) against each backend serving the module
6. merge                      only when 2–5 are green for every engine that serves the module
```

A backend **never** changes the contract by changing code. If an implementation finds the contract
wrong, the fix is a change to `contracts/` (and, where it changes a decision, the deviation protocol:
an ADR). The same holds for a client.

## 2. Bootstrapping v1 from What Exists (no rewrite)

The first `contracts/` is **not written by hand from nothing**. It is the as-built contract, frozen:

1. Run the as-built generator one last time (`openapi:generate`): code-first operations ∪ the remaining
   JSDoc (ADR-103 § 5).
2. Normalise it (`servers`, sorted keys, 3.1 only), split it per module into `contracts/openapi/`, and
   bundle it back. The bundle must equal the as-built document **semantically**: oasdiff both ways
   reports 0 changes. This is the **v1 baseline**, recorded with its hash.
3. Add what the as-built document lacks, as **additive** changes: the top-level error `code` on every
   error response ([`04`](./04-ERROR-CODES.md)); the 429 envelope gap ADR-103 recorded; the 76 routes
   on `openapiRoutes.undocumented.json` (each documented or explicitly marked internal);
   `x-module` on every operation (the gateway's routing key, [`07`](./07-PORTING-PLAYBOOK.md) § 2).
4. From then on `contracts/` is the source. `backend/openapi.json` stops being committed by the
   backend; the bundle `contracts/dist/openapi.json` replaces it everywhere it is read (Scalar
   `/api/v1/docs`, `api:types`, oasdiff's base).

## 3. Node: Generate Zod From OpenAPI (decided), With an Equivalence Check During the Migration

The owner asked us to choose between **generating** Zod from OpenAPI and **proving equivalence** between
hand-written Zod and the contract.

**Decision: generate.** Node's request and response validators become **generated code**
(`backend/src/generated/contract/<module>.ts`, not edited by hand, re-generated by
`npm run contract:generate`, checked stale by `contract:check`). Behaviour that JSON Schema cannot
express is not hand-written beside the schemas. It is a **named rule** in `contracts/rules/`
(`x-rule: <id>` on the schema or operation), implemented once per language in a rules module and
proved by `contracts/vectors/`.

| | Generate (chosen) | Prove equivalence (keep hand-written Zod, diff against `contracts/`) |
|---|---|---|
| Copies of each shape | **one** (the contract); Zod is output | two (contract + Zod), held together by a CI diff |
| What drifts | nothing silently — a stale generation fails `contract:check` | refinements, transforms and defaults that do not round-trip into JSON Schema drift without the diff seeing them (ADR-103's own experience: P6-08 compared keys, never types or bounds) |
| A second engine | uses the same procedure (generate its validators) | would need its own equivalence prover per language |
| Cost | a generator to choose and pin; cross-field rules moved to named rules; the generated Zod is less idiomatic | lower first cost; permanent double-writing — the reason ADR-103 rejected design-first YAML |

**The generator** is chosen by the first Phase 32 card under the package rule (the owner allows swaps
when proven). Candidates: `@hey-api/openapi-ts` with its Zod plugin, `orval` (Zod output),
`openapi-zod-client`. The criteria:

- full OpenAPI 3.1 support (`type: [x, "null"]`, `const`, `prefixItems`), Zod 4, ESM/CJS output that
  loads under `tsx` and the compiled `dist/`;
- `x-*` extensions passed through (to attach `x-rule`);
- deterministic output; maintained; permissive licence.

A generator that cannot express one of the contract's constructs is a reason to simplify the contract
construct, not to hand-edit generated code.

**Equivalence check, during the migration only.** Modules move one at a time ([`07`](./07-PORTING-PLAYBOOK.md)
§ 8 order; Phase 32 cards). While a module still validates with its hand-written Zod (`validators/`,
`@callibrator/contracts` request schemas), CI runs the **as-built code-first generator for that module**
and requires **oasdiff = 0 both ways** against `contracts/` for its operations. When the module flips to
the generated validators, the check is deleted for it. The equivalence list **only shrinks** (the
`openapiRoutes.undocumented.json` pattern).

What does **not** change in Node: `validate(schema, { from })` stays the only middleware form (now fed
by generated schemas), `validated(req, schema)` in handlers, the 400 envelope, the tenant hooks,
`sql()`.

## 4. Clients

- **`packages/api-client`** (ADR-134) generates its types from `contracts/dist/openapi.json` instead of
  `backend/openapi.json`. Nothing else in the client changes. The web's `frontend/src/api/typed.ts`
  and its 56 service files keep their shape, with types from the same generation.
- **`packages/i18n`** generates its error-code key list from `contracts/errors/codes.yaml`. A code
  without an `id` and an `en` message fails the package's test.
- **Realtime clients** (`socket.io-client` on the web; none on mobile in v1) get event-name and payload
  types generated from `contracts/asyncapi/` ([`05`](./05-REALTIME-ASYNCAPI.md)).
- Clients never import a backend package and never branch on an engine. A capability the serving
  engine has not implemented is hidden by **`GET /api/v1/meta`** ([`07`](./07-PORTING-PLAYBOOK.md) § 5), not by
  a client version.

## 5. ADR-103's Gates, Re-pointed

| ADR-103 gate | Re-pointed |
|---|---|
| **Stale** — `openapi:check` fails when the committed document differs from the generated one | `contract:check`: the bundle `contracts/dist/openapi.json` equals a fresh bundle of `contracts/openapi/**`; every **generated** artefact (Node Zod, client types, i18n code keys, AsyncAPI types) equals a fresh generation |
| **Invalid** — Spectral (`backend/.spectral.yaml`, ERROR for code-first, a shrink-only legacy baseline) | Spectral moves to `contracts/.spectral.yaml`, with the same rules plus: `x-module` required; every error response references the error envelope with `code`; every `code` used exists in `codes.yaml`; every `x-rule` exists in `rules/` with vectors. The legacy baseline (18 on 2026-09-30) carries over shrink-only. **AsyncAPI** validated by the AsyncAPI parser |
| **Breaking** — oasdiff `breaking` against `origin/main`, `--fail-on ERR` | oasdiff on `contracts/dist/openapi.json` vs `origin/main`'s. **v1 is additive only**: a breaking change to a `/api/v1` operation fails, with no exception. It goes to `/api/v2` ([`03`](./03-BEHAVIOUR-SPEC.md) § 15). The mobile rule of `docs/MOBILE/08` § 5 (check against the oldest supported app's snapshot) is the same command with another base |
| **Undocumented route** — `openapiRoutes.p925` (every mounted route has an operation) | per engine: every route the engine mounts is an operation in `contracts/` whose `x-module` the engine serves, and **every operation of a module the engine claims** (`/meta` capabilities) is mounted. Node: the existing guard reading `contracts/`. Other engines: the conformance suite's route-inventory check ([`06`](./06-CONFORMANCE-SUITE.md) § 3.6) |
| **Frontend types current** — `api:types:check` | unchanged, reading `contracts/dist/openapi.json` |
| **`x-permission` cannot lie** — compared with the mounted chain (`openapiRoutes.p925`) | stays for Node. For another engine, the conformance suite's permission matrix proves the gate from outside ([`06`](./06-CONFORMANCE-SUITE.md) § 3.3) |

`make verify` and CI run the contract gates **before** any backend's tests: a red contract fails fast.

## 6. Who Reviews a Contract Change

A change under `contracts/` needs a reviewer who owns **a client** (web or mobile), not only the
author of the backend change. The contract is the clients' document. Breaking `/api/v1` is not a
review decision: the gate refuses it.
