## The pattern (ADR-087 Amendment 13), as applied

- `export =` of one object literal in the original key order. No other export (Amendment 15); types are module-local interfaces.
- Internal `exports.x()` calls now go through that object: `dataRetention` (`service.isOnLegalHold` ×2, `service.purgeExpiredRecords`) and `tenantLifecycle` (`service.checkGracePeriodExpired`, `service.offboardTenant`). Each harness proves the late binding by replacing the export.
- Load-time destructures are kept as captures at load (`import { x as loadedX }` then `const x = loadedX`). `redis` is destructured from its default import.
- Lazy requires stay lazy, typed inline: every `require("../models")` in tenantHierarchy and customDomains; Tenant, AuditLog and User, plus `gdpr.service` (still JavaScript, typed by the one member used) and `upload.util` in dataRetention; `emailQueue.service` in customDomains; and the barrel, migration 0030 and the platform id in `tenantLifecycle#hardDeleteOffboardedTenant`.
- `process.env` goes through `config/env`. `envOr` is used where the `.js` had `X || "default"`. `parseInt(process.env.X)` became `parseInt(String(env("X")))`, which gives the same result for every input because `parseInt` applies ToString.
- `||` is never `??`. Each such line carries a reasoned directive; `tenant.service` carries one file-level directive (the Amendment 14 §4 precedent).
- `db.Sequelize.Op` / `.Transaction` are still read at call time through an intersection type, since Sequelize's typings omit both statics. `db.sequelize` in `fetchTenants` is typed the same way; the barrel sets it at load.
- Kept as built, each with a reason: `await logger.warn(...)` (the extra tick), `rawAttributes` (deprecated), the `{ status, message }` object `fetchTenants` throws, the unused `resultData` (`void`), and `result.complete === false`.

**Accepted differences:**
- Formerly anonymous functions are now named after their key: 8 in tenantHierarchy, 8 in customDomains, 9 in dataRetention, 10 in tenantLifecycle, 11 in tenant, 2 in tenantUpload, 0 in networkSecurity.
- Two unused load-time names are gone:
  - tenantLifecycle's `isEnabled`. `featureFlag.service` is still loaded at the same point, as a side-effect import.
  - tenant.service's `MAX_LIMIT`. Reading a constant has no effect.

## Findings

- **A-326 (medium, measured):** `updateTenant` writes the validator's upper-case status into the lower-case ENUM.
  - On PostgreSQL 18 it fails with `invalid input value for enum enum_tenants_status: "ACTIVE"`, which answers 500.
  - This happens both for a tenant admin resubmitting the current status and for a super admin.
  - Kept with `@ts-expect-error`.
- **A-327 (low, measured):** an edit with `email: null` or `""` fails the model's `notNull` / `isEmail` check (500, not 400). Kept with `@ts-expect-error`.
- **A-328 (low):** `createTenant` writes `createdBy`, which is not a Tenant attribute; it is dropped. Kept with `@ts-expect-error`.
- **A-329 (low, found by the live probe):** a root tenant has no `tenant_hierarchies` row, so its tree lists no children and its descendants are `[]`. Identical in the JavaScript.
- **Noted, not a defect:** customDomains' `domainNotificationRecipients` queries `users.id = null` for an API-key actor. That matches no requester, as intended; one `@ts-expect-error` explains it.
