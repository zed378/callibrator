## What surprised me (→ ADR-126 Amendment 3)

1. **The spec contradicts itself on `idempotency_keys.user_id`:** it says NOT NULL, and it also says "exactly one of user / API key". The CHECK wins, so the column is nullable.
2. **Two uniques in the spec were global** (the results' legacy key and the linear chain). Both are now per tenant. The verification token stays global, by ADR-126 Am. 2 § 3.
3. **`DataTypes.NOW` is never a column default.** The first live run failed with 23502 on `performed_at` for a raw insert. 0126 now sets `now()` on `performed_at`, `received_at` and `signed_at`.
4. **The 0057-after-0119 trap, in this card's shape:** with 0117's functions put back, every result insert fails with **42703** (`record "new" has no field "device_id"`). That is the fail-before of the `result` branch.
5. `location_id … SET NULL` acts as RESTRICT on a submitted session, because the trigger refuses the SET NULL. Recorded as an implication.
