## The name freeze

**How Umzug keys a migration.** `schema_migrations` stores the **name string from the manifest** in `src/config/migrator.js`. It does not store the file name. Every historical name ends `.js`, because the manifest copied the glob resolver's names.

**Design: nothing in the manifest changes.**
- The names still end `.js`, whatever the file's extension. A name is `<module path>.js`, fixed when the migration is first applied.
- The `require`s were already extensionless:
  - tsx (`npm start`, `migrate*`) and jest resolve the `.ts` source;
  - `dist/` resolves the `.js` that `build:dist` compiled;
  - plain `node` cannot run source anyway (ADR-087 §1).
- `migrator.js` gained two comments only: the header example and a P9-23 note above the manifest.
- The context is still `db.getQueryInterface()`.

**The guard: `backend/src/tests/migrations/manifestNames.p923.test.ts`** (5 tests). It was written **before** any file was renamed.
- `FROZEN` is the 63 names 0001…0090, typed by hand. It equals the first 63 `schema_migrations` rows of a PostgreSQL 18 database migrated by the `.js` migrations. That was checked live twice: on 2026-09-29, and again on the final tree.
- It reads the names from Umzug's own `migrations()`, with `config/index` mocked to an unconnected Sequelize. It asserts the first 63 equal `FROZEN`, in order.
- For every entry, frozen or newer, it asserts that the name is `<module>.js`, that the names are sorted and unique, and that the module exists **exactly once** as `.js` or `.ts`.
- It asserts that every `NNNN-*` file on disk is registered.
- It asserts that the context is not `{ queryInterface }`.
- **It fails when a name changes.** With 0019's name "tidied" to `"0019-add-signature-crypto-fields"`, 2 of 5 tests failed. `migrator.js` was restored and its hash checked.

**The card said 19 names.** The manifest had grown to 63 by the time conversion began. The card is corrected (the DoD now says 63). Migrations 0091–0102 were written TypeScript-first by other lanes with `.js` names. They are outside `FROZEN` but inside the per-entry rules.

**Rules** (`p923/BRIEF.md`). Only type annotations and casts are added, and they are erased. The runtime-neutral changes allowed:
- `module.exports = {…}` became `export = {…}`, with the same object literal and the same key order.
- An in-function `require("sequelize")` became a top-level `import`. The module is already loaded, so the binding is the same.
- `process.env.DB_APP_ROLE` became `env("DB_APP_ROLE")` (0057). It reads the variable at call time, as before.
- A `require` of a still-JavaScript service stays exactly where it was, typed, with a reasoned `no-require-imports` disable (the ADR-087 Amendment 11 precedent):
  - `kms.service` in 0022 and 0035 (lazy);
  - kms, signingKeyWrap, keyRotation and mfa in 0058 and 0086 (top level).
- Lint-driven spellings that do not change behaviour:
  - `x["col"]` for index-signature access;
  - `${String(n)}` in template literals;
  - `() => undefined` for an empty `.catch` callback;
  - one unused `let` dropped in 0005;
  - one unused `require("path")` dropped in 0012.
- **Never changed:**
  - `||` stays; it is never turned into `??`;
  - no `?.` or `!` added;
  - no statement reordered;
  - no SQL, message or refusal condition altered.

Where lint asked for a behavioural change, the code stays as written with a line-level disable reading `-- as built`:
- 37 × `prefer-nullish-coalescing`, including the 16 frozen D-29 `context.queryInterface || context` fallbacks, kept literally so D-29's regex still finds them;
- 6 × `prefer-optional-chain`;
- 2 × `no-empty-function` (async no-op `down`s);
- 1 × `require-await`;
- 1 × `no-meaningless-void-operator`;
- 1 × `restrict-template-expressions`;

## Identity evidence (scratch `p923/`)

**Recording harness (`identity.js`).** For every migration it loads two things:
- the ORIGINAL `.js`, snapshotted before conversion into `id/orig/`. The snapshot was checked against `git show HEAD:`; the only difference was CRLF, which template literals normalise;
- the `.ts` compiled by TypeScript 7 under `tsconfig.build.json`'s options (`compile.sh`).

It runs `up` and `down` for 300 seeds each against a seeded-fuzz QueryInterface.
- **What the fakes return:**
  - `describeTable`: random column subsets, or one of three errors;
  - `showAllTables` / `showIndex`: random results;
  - `sequelize.query`: rows built from the migration's own literals and identifiers, `[rows, meta]` or SELECT arrays;
  - `transaction`: runs the callback, then commits or rolls back;
  - `getDialect`: `postgres` or `mysql`;
  - a 4% random rejection on every call;
  - `DB_APP_ROLE` cycled through unset, `""`, `none`, a valid name and an invalid one.
- **Stubs.** The JavaScript services, the logger, `fs` and `storagePath` are stubbed as recorders. The stubs call any callbacks handed to them.
- **Recorded:** every call with its arguments (SQL, options, DataTypes), every stub call, every unknown property read, the return value, and the thrown error's class and message. It also compares each module's export names, order and non-function values.

**Result: 37,800 runs, 0 differences.**

## For the ADR-087 amendment

### Amendment N (2026-09-30) — P9-23: the migrations are TypeScript; their names are frozen

1. **Names are strings in the manifest, not files.** Umzug keys `schema_migrations` by the manifest's name string. All 63 historical names (0001–0090) end `.js`, and they stay that way. A migration's name is `<module path>.js` for a `.ts` file too, fixed when first applied and never changed.
   - `migrator.js`'s requires are extensionless, so tsx and jest load the `.ts` and `dist/` loads the compiled `.js`. The manifest itself did not change.
   - `manifestNames.p923.test.ts` freezes the 63 names. It was typed by hand from a PG18 database's rows, written before any rename, and seen to fail on a tidied name. It also refuses a module present as both `.js` and `.ts`, and an unregistered file.
2. **Conversion is type-only, with a closed list of runtime-neutral edits:**
   - `export =` with the same object;
   - an in-function `require("sequelize")` becomes a top-level import;
   - `env()` in place of `process.env`;
   - JavaScript services stay `require`d in place, typed (Amendment 11's precedent).

   `||` is never turned into `??`, and the 16 D-29 fallbacks are kept literally. Lint's behaviour-changing suggestions are refused with `-- as built` line disables.
3. **Evidence standard for a migration:**
   - (a) a recording seeded-fuzz QueryInterface, original `.js` against compiled `.ts`, `up` and `down`, including refusal branches (37,800 runs, 0 differences);
   - (b) a normalised AST diff whose remaining lines are each argued neutral;
   - (c) live PG18: identical `schema_migrations`, schema-only dump and grants on a fresh build, and nothing pending on an upgrade.

   (a) alone missed an injected `||`→`??` change, so (b) is required, not optional.
4. **`src/migrations/**/*.ts` keeps Amendment 12's exemption** from the direct-query rule. Migrations still issue DDL and raw SQL through the QueryInterface outside any tenant.
5. **Bad implications:**
   - 0056 now reaches `fs`/`crypto`/`path` through `__importStar` namespace wrappers. This is live delegation, but a different object from the module.
   - Four migrations still `require` JavaScript services and get their types from local casts, not from the services. The casts can drift until Stage C converts those services.
   - The identity fuzz covered 63–75% of the lines of 0030, 0037, 0066 and 0086; their unit suites cover the rest.
