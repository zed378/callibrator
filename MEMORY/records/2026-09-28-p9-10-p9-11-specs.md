## Hook

Sequelize's documented typing recipe for models, `createdAt: DataTypes.DATE` in `init`, **changes
the column** (it drops `allowNull: false`). Two constructs the `where` type rejects are
load-bearing:

- **`where: null` in `includeDeleted`:** it clears the defaultScope's predicate when the two
  scopes are combined.
- **`is_deleted` as the defaultScope key:** it lets `user.service#assertIdentityFree` override
  that key and find soft-deleted identity holders.

On the validation side there are **five** validation-400 surfaces, not one, and the documented
shape (`"Validation failed"`, field detail mapped by the frontend) matches none of them.

## Why

Both cards are marked "Spec required". P9-10's pattern will be copied by 71 models. P9-11's DoD
asks for a byte-compatible 400 "asserted by a contract test per validator". Those tests have to
exist, and pass against Joi, **before** a Zod conversion can be held to them.

## Alternatives Considered

- **Module-level model classes** (the standards document's example). Rejected: about 14 tests
  re-`init` a factory with their own Sequelize, and a shared class would be rebound (P9-10
  spec, item 1).
- **Declaring timestamps in `init`, or `omit`-ing them from the attributes type.** The first
  changes the column. The second makes `where: { createdAt }` a compile error across the
  services. Chosen instead: one `initModel()` helper with one contained assertion.
- **Rewriting the defaultScope to `isDeleted`, and `where: null` to `{}`.** Rejected on the
  probes.
- **A custom typed ESLint rule for default-scoped includes.** Rejected: there is no rule
  infrastructure, and ADR-064 item 6 already makes the source test the lint rule. It is
  extended to `.ts` instead.
- **Contract tests against a mocked `response.util`.** Rejected: a mock proves the test. The
  harness runs real Express 5, real `express.json()`, the real `errorHandler` and real fetch,
  and compares body **text**.
- **One test file for all validators.** Rejected: one suite per validator lets P9-11 convert
  file by file, each conversion keeping its own suite green.

## What Surprised Me

- **`validate(schema)` answers `"Validation Error"`.** Both documents say `"Validation failed"`,
  which is only what the per-file helpers throw.
- **The middleware never merges `req.params`.** The merge lives in controllers, and they
  disagree on precedence: `tenant` lets the path win; `dataRetention`, `featureFlag` and
  `tenantLifecycle` let the body win.
- **The frontend reads `message` only.** No frontend code reads `details`.
- **A helper's `errors` never reaches the wire.** `asyncHandler` drops it, and outside
  production sends `"details":"[object Object]"`.
- **Metered billing has a second live validation middleware.** Its production 400 says only
  "An unexpected error occurred…", because a plain `Error` is not exposable.
- **`jsonShape.util` (a util) imports `iot.validator`.** Under `allowJs: false`, both must be
  `.ts` before the first model with a JSON column.
- **Five guard tests walk `.js` only:** `includeRequired.d12`, `unscopedModels.d17`,
  `jsonShape.d27`, `bodylessBody.a09` and `swaggerValidatorAlignment.p608`. A converted file
  silently leaves them.
- **`audit.validator` and `webauthn.validator` export no schema, and nothing imports them.**
- **Zod is in the root `node_modules` only as a transitive dependency (4.6.5).** No
  `package.json` in the repository declares it.
- **My own first expectation for surface B was wrong.** I assumed abortEarly, but the schema
  sets `abortEarly: false`. The run caught it, and the expectation was corrected to the joined
  two-message string.
