# 2026-09-30 — P10-04 (frontend) and P10-10 (button): identifier-first sign-in, passkeys

**Cards:** P10-04 frontend (backend part: ADR-108, `2026-09-30-p10-backend-access-requests-passkey.md`), P10-10 frontend · **ADR:** ADR-098 §9, Amendment 1 rows 7, 10 · **Status:** P10-04 DONE in code (frontend and backend); both IN REVIEW until the P10-13 live E2E

## Built

- `app/login/page.tsx` is a server component: `generateMetadata`, the split-screen `components/public/AuthShell.tsx` (left panel ≥ 1024 px: product glimpse, motif, one line, **no claims**, `aria-hidden`; right: back link, language form, `<main>`), and the client `LoginPanel` given only the `auth.*` strings. No Motion (it drove the old tab indicator).
- **One `<h1>` at every width, in the form** — *Masuk ke Device Calibrator*, or *Masuk ke {tenantName}* on a tenant-pinned build, whose logo (never its colour) shows above it.
- Identifier-first (`hooks/useLoginForm.ts`, `components/IdentifierForm.tsx`): step 1 posts `POST /auth/login/discover`; `next: "sso"` redirects to the IdP (the user never picks SAML/OIDC); a missing endpoint or any non-429/network failure falls back to the password step. Step 2 (`PasswordLoginForm.tsx`) shows the identifier with *Ganti akun*, `autocomplete="current-password"`, a hidden `username` field for password managers, *Lupa kata sandi?* → `/forgot-password`, a show-password toggle with `aria-pressed`. "Remember me" gone.
- Organisation-code fallback (`SsoLoginForm.tsx`): the code only, `POST /auth/sso/start`, one generic refusal for everything (`auth.sso.unavailable`); `/login?org=<code>` starts that tenant's SSO on load.
- MFA (`MfaLoginForm.tsx`): one pasteable field (non-digits stripped), `one-time-code`, the instruction tied with `aria-describedby`, the recovery-code switch always visible; an expired MFA token returns to the password step with *Kode sudah kedaluwarsa*.
- Messages mapped by status/code (`i18n/apiErrors.ts#signInMessage`), never the backend's English: 401 credentials; 429 minutes = ceil(`retryAfter`/60) from the body or the `Retry-After` header; 423 locked; 403 suspended organisation; network/5xx.
- **A-288 (ADR-100, agreed with the security agent):** a 403 `LOCATION_REQUIRED` asks for the position ONCE (`enableHighAccuracy: false`, 10 s, `maximumAge` 60 s) and resends the same request with `location`; denied → the message plus *Akses lokasi tidak diizinkan*, nothing more sent; the position is then sent proactively on the MFA step; `NETWORK_POLICY` is shown without asking. `authStore.login`/`completeMfaLogin` and `authService.mfaLogin` take an optional `location`.
- The first-password step (P10-16, the bootstrap agent's) restyled and translated with its behaviour, exports (`PASSWORD_RULE`, `meetsPasswordRule`) and tests intact; its 401 copy made neutral for both audiences (Q-49).
- `/sso-callback` routes through `destinationAfterSignIn` (05 §5.1) instead of always `/dashboard`.
- **Passkey (P10-10):** `lib/passkey.ts` (WebAuthn only, no library: base64url options → `navigator.credentials.get` with no identifier and no `allowCredentials`, `userVerification: "required"`, the assertion → @simplewebauthn JSON; a cancelled ceremony is null), `authService.passkeyOptions/passkeyVerify`, `authStore.loginWithPasskey`, a Next route `app/api/v1/auth/passkey/verify/route.ts` that writes the session cookies like the login route and strips both tokens (F-62), refuses cross-origin posts, and forwards the scheme (A-310). The button renders only where `PublicKeyCredential` exists (`useClientValue`, never on the server). A `LOCATION_REQUIRED` answer runs one new ceremony with the position. Conditional UI (autofill) is **not** built.
- `api/client.ts` `CREDENTIAL_ENDPOINTS` + `login/discover`, `sso/start`, `passkey/verify`, `invitation/accept`, `access-requests` (a 401 there never triggers a refresh or redirect).
