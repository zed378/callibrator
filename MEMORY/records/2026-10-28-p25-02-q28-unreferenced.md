# P25-02: Q-28's unreferenced photo files, a run-level finding

**Date:** 2026-10-28 · **Card:** P25-02 · **Status:** PARTIAL (the user section not built; R-9 covers the accounts) · **Decision:** ADR-129 Am. 12 item 11 · **Spec refs:** `docs/UPSTREAM/03` § 7 (Q-28: "162 missing; 3,360 unreferenced"), § 6

## Hook

Q-28 has two halves. The missing half (a row names a file that is not on disk) has been counted
per facility since 2026-10-27. This adds the other half: a file on disk that no row names. That
file has no device, so it has no facility either, and the report had nowhere to put it.

## What changed

**[`backend/src/services/upstreamDataQuality.service.ts`](../../backend/src/services/upstreamDataQuality.service.ts)**
gains `unreferencedFiles`, which counts files on disk that no staged row names:

- **On disk:** the catalogue of the provider's image-import manifests, read with step 9's own
  `manifestsOf` and `catalogueOf`, limited to the `foto_depan` / `foto_sn` folders.
- **Named:** every staged device row of the run, parsed with step 9's `photoNameOf` into
  `<folder>/<name>`, the key step 9 looks up.
- **Quarantined at ingest:** such a file (a virus, a refused type) was still on disk, so it
  counts too.

It also changes how the existing Q-28 answers:

- The facility Q-28 is now `pass`/`flagged` on the missing half alone. It no longer answers
  `manual` when nothing is missing.
- The manifests are read on the application's connection **before** the transform transaction,
  as the transform service does.

**[`packages/contracts/src/upstreamDataQuality.ts`](../../packages/contracts/src/upstreamDataQuality.ts)**
adds a required `runFindings: dataQualityFinding[]` for findings with no facility. The change is
additive, and the frontend does not consume this endpoint.

Also updated: the OpenAPI description, `openapi.json`, the frontend `schema.d.ts`, and the
as-built lists in 05 § 7, `docs/BACKEND/13`, the runbook, `PHASE-25`, `PROGRESS` and ADR-129 Am. 12.

## What surprised me

The first live run failed in `manifestsOf`. Its `UpstreamFileImport.findAll` ran inside the
report's transform-connection transaction, and the transform role cannot read
`upstream_file_imports`. The unit test had mocked `manifestsOf`, so it passed: a mock proves the
client, not the contract. Moving the read before the transaction, as
`upstreamSqlTransform.service` already does with `loadTransformFiles`, fixed it.
