## What surprised me (findings that changed the design)

1. **`04` § 5 maps the physical check and consumables wrongly.** It reads `-1` as "not applicable" for every checklist; the upstream report prints physical `1/0/-1` as *Baik / Cacat-Rusak Ringan / Rusak Berat* and consumables as *Iya / Tidak / Habis*. Imported as written, every heavily damaged device would have read "N/A". Corrected (outcome sets per section).
2. **The read gate named in ADR-125 and the Phase 12 DoD (`equipment`) is the parent menu.** Device routes are gated by `calibration`; `equipment` gates only attachments. Corrected.
3. **A paranoid catalogue would have hidden evidence.** A `defaultScope` turns every include into an INNER JOIN (A-75); a session including its retired version would have vanished. The catalogue is not paranoid; `retired` is the only removal.
4. **The commonest upstream reference value is a tolerance around the setting** (`± N %`, about half of 184), which ADR-125's single `limit_value` could not hold. About three quarters (139 of 184) of the performance references and all electrical-safety limits parse to an evaluable structure; the rest are printed and decided by a person.
5. **Upstream limits use decimal commas too** (`≤ N,N Ω`), not only measured values.
6. **P21-01 could not compile** before P20-06: its read gates name the `ipm` / `ipm-templates` slugs and `SeededMenuSlug` makes an unknown slug a type error. Dependency added.

## Decisions (ADR-125 Amendment 1; alternatives and bad implications in `MEMORY/DECISIONS.md`)

Outcome vocabulary per section · read gate `calibration | ipm | ipm-templates` · structured limits with hard (`valid_*`, 400) and soft (`warn_*`, flagged) ranges, `flag` dropped · catalogue not paranoid, no `defaultScope`, DELETE refused by trigger · `calibration_devices.device_type_id` RESTRICT · `discarded` drafts, version numbers at publish, exactly one publisher (user or `system:catalogue-seed` / `system:upstream-import`) · a base publish rebases every published type version in one transaction · template items always name their library definition · electrical-safety pass/fail computed and not overridable, performance pass/fail the technician's with the computed one kept beside it · one shared parser/evaluator in `@callibrator/contracts` (decimal strings, scaled-integer comparison, no unit conversion) · the published document carries active device types and its ETag covers them · accepting a proposal copies nothing into the global tables · no socket event, no webhook, no per-type IPM interval.

**For the owner / SME (none blocks the migration):** the seeded warn ranges (notably mains 198 … 242 V) and the "no override of a computed electrical-safety fail" rule, at UAT (P26-01).
