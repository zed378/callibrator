# 2026-09-30 — P9: every backend module must load (a load gate), and `export =` stands alone

**ADR:** ADR-087 Amendment 15 (and Amendment 16, which places the P9-23 lane's migration text). **Asked by:** the coordinator, after the backend failed to boot with typecheck and jest green.

## What was wrong

Two modules threw when first required:
- `certificate.model.ts`: `jsonShape is not defined`. The Q-50 lane fixed it.
- `webauthn.service.ts`: `webauthn_service_module is not defined`. The P10 lane fixed it.

The cause of the second was an `export interface` beside `export =`, which tsx/esbuild emits as a reference to an undefined binding.

Nothing in `make verify` or CI executes a module's top level unmocked through the production loader. CI's boot job runs tsx over `src/`, but the image runs `dist/`, and CI has never run on GitHub (P7-01).

## The change

- **`backend/scripts/load-check.ts`**, run as `npm run load:check`:
  - Default mode: `dist/` under plain node. `-- --src`: `src/` under tsx.
  - Pass 1 requires every module. Pass 2 is a fresh process in index.js's boot order.
  - Configuration is placeholders: the database and Redis on port 1, random secrets, `ACCESS_REQUEST_IP_PEPPER`.
- **`backend/package.json`:** the `load:check` script.
- **`Makefile`:** a `load-check` target, and `verify` now ends `… test build load-check`.
- **`.github/workflows/ci.yml`:** a new job, `backend-load`, running `build:dist`, then dist mode, then src mode.
- **`backend/eslint.config.js`:** `EXPORT_EQUALS_ALONE`. In a module with `export =`, any other export is an error. It is spread into all three `no-restricted-syntax` blocks.
- **Documentation:**
  - ADR-087 Amendment 15.
  - `docs/ENGINEERING/04-TYPESCRIPT-STANDARDS.md`: the conversion table row names the enforcement. The rule was already written there; nothing enforced it.
  - The verify-stage lines in `CLAUDE.md` and `AGENTS.md`.

## Evidence

- **The tree:**
  - `npm run build:dist`: 206 JavaScript files copied, 336 TypeScript files compiled.
  - `npm run load:check` gave "every module: 527", "boot order (index.js): 102" and "OK (dist via node)".
  - `npm run load:check -- --src` gave 527 + 102, "OK (src via tsx)".
- **Each mode bites on its defect shape:**
  - **src mode:** the planted `src/utils/zzLoadProbe.p9.ts` (`export interface` + `export =`) failed it with `zzLoadProbe_p9_module is not defined`.
  - **dist mode:** the planted `dist/src/utils/zzLoadProbe.js` (an undefined `jsonShape`) failed it with `jsonShape is not defined`.
  - **The lint rule:** it fails the same probe (`no-restricted-syntax`, the rule's message).
  - Both probes were deleted, and each deletion was checked with `ls`.
- **Before the placeholder was added,** the first src run reported `accessRequests.route` refusing to load in production without `ACCESS_REQUEST_IP_PEPPER`. That is a deliberate P10-05 configuration refusal, so the pepper is now a placeholder.
- **`nodeVersion.a257` and `prePushHook.a19`** passed 25/25 after the CI edit. `npm run ratchet` was at the floor (905). Lint is clean on the script, apart from one reasoned `process.env` disable: the child inherits PATH.

## Not done / open

- The gate proves loading, not readiness. `make verify` still has no boot, and CI boots only through tsx.
- A pre-push hook step was not added: dist mode needs a roughly 4-minute build.
