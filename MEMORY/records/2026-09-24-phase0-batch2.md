## What Changed

| | |
|---|---|
| **Sessions are revocable** (A-48) | Access tokens carry `sid`; every request checks the session is live (Redis, ≤60 s, falling back to the DB). **Logout had never revoked anything** — it threw on a missing argument, and the 500 was swallowed by the frontend |
| **Token purposes are enforced** (A-59, A-52) | The emailed activation token, the MFA-pending token and the socket token were all full bearer access tokens. Each is now a typed purpose token, accepted by one route only. SSO tokens carry `sid` |
| **SSO hand-off** (A-60) | Access and refresh tokens no longer travel in the redirect URL. A 60-second single-use code is exchanged server-to-server, and `sso-session` no longer stores an unverified token |
| **Audit rows inside the transaction** (A-41, A-42) | 25 named mutations write their audit row in the same transaction, and a failed audit write rolls the change back. It is logged through winston, not `console` |
| **E-signatures had no audit trail** (A-61) | Every sign and revoke committed the signature, then failed its audit insert on an out-of-ENUM action, and returned a 500 |
| **The approver is the caller** (A-62) | Certificate approval, and QMS CAPA approval, no longer take the approver from the request body |
| **Webhook secrets** (A-51, F-18) | Generated server-side, stored through KMS, rotatable, rotated on a URL change, and shown once in the UI |
| **Error leakage, `dynamicAccess` half** (A-13) | Forwarded to the global handler — together with the search probe, which would otherwise have failed **open** |
| **Tenant lifecycle** (W-01) | Six missing columns (migration `0023`), valid ENUM values, `node-cron`, offboarding audited inside its transaction. Verified on PostgreSQL 18.6 |
| **Infra** | `/api/` goes to the frontend in every manifest; the backend image builds from the repo root with `npm ci` and verified TLS; `make migrate` no longer starts a second server; the health claims are true; the VM bind mounts are chowned by a `volume-init` service |

## Found While Fixing, Not Fixed

**Two are critical and are next:**

- **A-63.** Any authenticated user can edit or suspend **any tenant**. `dynamicAccess`'s `checkSelf`
  bypass trusts a body `userId` and skips the tenant check.
- **A-64.** `PUT /certificates/:id` can set `status: "approved"` or `"signed"`, bypassing both
  re-authentication and the e-signature.
