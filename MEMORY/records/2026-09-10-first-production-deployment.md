# First Production Deployment — Nine Defects the Tests Could Not See

**Date:** 2026-09-10
**Kind:** deployment · defect record
**Related:** [`2026-09-10-monorepo-restructure-and-as-built-docs.md`](./2026-09-10-monorepo-restructure-and-as-built-docs.md) · `TASKS/PHASE-0-FOUNDATION.md`

---

## What Happened

The platform was deployed to a single host running nine other compose projects, behind an existing Cloudflare tunnel, and reached working end-to-end: seven healthy services, browser login, tenant-scoped lists, Socket.IO over the proxy, and the public certificate verification page.

Getting there took **nine defects**, and the shape they share is the point of this record: **not one of them was reachable from a test.** Every one lives in the gap between the code and the thing that runs it — the image, the ignore file, the proxy, the environment, the empty database.

3,863 backend tests passed throughout. So did every local `npm run dev`.

## The Nine

| # | Defect | Why nothing caught it |
|---|---|---|
| 1 | `backend/.gitignore` line `storage/` — unanchored, so it matched **any** directory named `storage` at any depth, silently excluding `src/services/storage/` (6 files) | every working tree had the files; only a **clean clone** crashed, with `Cannot find module './storage'` |
| 2 | `KMS_MASTER_KEY` — a **fourth** required secret, absent from `.env.example`, the docs and `make secrets` | it throws only in production, and the message goes to `log/activity/exception/<date>.log`. `docker logs` was **empty** |
| 3 | nginx routed `/api/` to the **backend** | Next.js owns `/api/v1/*`: the login route sets the httpOnly `auth_token` cookie and the catch-all injects `Authorization` from it. The backend returned **200** the whole time; the browser simply never held a session |
| 4 | `HOSTNAME` unset for the Next standalone server | it binds `process.env.HOSTNAME`, and Docker sets that to the **container ID** — a healthy process listening where nothing could reach it |
| 5 | `frontend/Dockerfile` referenced a `bun.lock` and a `build:docker` script that do not exist | nobody had built the image |
| 6 | the `next-bun-compile` adapter was always on in production | `next build` failed with `ENOENT: .next/next-server.js.nft.json` |
| 7 | `bun` absent from the builder stage | `next-bun-compile`'s postinstall shells out to it purely to create a symlink; `npm install` exited **127** |
| 8 | `wget` absent from the backend image | its own `HEALTHCHECK` invokes it; `/health` returned 200 while the container reported unhealthy |
| 9 | bind-mounted volumes owned by root against a UID-997 image | `EACCES: permission denied, mkdir '/app/log/activity/'` |

Plus one that is not a defect but reads like one: **the database is never seeded.** Migrations create 72 tables and nothing populates them, so `POST /auth/login` answers 500 on an empty `users` table.

And one genuine application bug, found by clicking through the deployed product: `GET /menu-groups/menu-groups/admin` answered **500** with `Cannot read properties of undefined (reading 'roleId')`, because **Express 5 no longer defaults an absent body to `{}`** and the handler read `req.body.roleId` on a GET route.

## The One Worth Keeping

Number 1. The repository was **missing six committed source files, and no local checkout could tell** — the working tree had them, the tests imported them, the app ran. Only somewhere nobody had ever cloned did the module disappear.

An ignore pattern without a leading slash is a glob against every directory in the tree. `storage/` and `/storage/` are not the same rule, and the difference is invisible until it costs you a deployment.

## What Changed

- All nine fixed in the repository, not only on the host — the fix that lives only on the server is the next deployment's defect.
- `KMS_MASTER_KEY` generated by `make secrets` and refused by `make check-env`.
- `docs/DEVOPS/03-REVERSE-PROXY.md` **corrected**: it had documented `/api/*` → backend, which is precisely defect 3.
- `ALLOW_SEEDING`, `BACKEND_INTERNAL_URL` and the first-boot procedure documented in `deploy/README.md` and `docs/BACKEND/11-CONFIGURATION.md`.
- `make ENV=vm` now selects the vm overlay that already shipped.

## The Lesson

The test pyramid in `docs/TESTING/` has four layers and **none of them is the deployment**. A unit test proves a function; an E2E spec proves a flow against a running server someone else started. Nothing in the suite proves the image builds, the ignore file is honest, the proxy routes, or the secrets are named.

The cheapest available control is a **clean clone build in CI** — which is P7-01, and which would have caught defects 1, 5, 6 and 7 outright.
