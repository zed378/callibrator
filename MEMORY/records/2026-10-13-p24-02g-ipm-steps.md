# P24-02g: the upstream transform's IPM steps (sessions and results)

**Date:** 2026-10-13 · **Card:** P24-02g (the last part of P24-02) · **ADR:** ADR-129 Amendment 9 · **Status:** DONE.

With this part, every step of P24-02 is built. The transform stays **not available** (409, `TRANSFORM_NOT_BUILT`) because step 9 (attachments) belongs to **P24-03**, which is still BLOCKED (P17-05, UD-18). **The end-to-end synthetic proof of the whole transform is therefore pending** until P24-03. What is proved here runs every step except 9, through the real runner, on PostgreSQL 18.

## What was built

| | |
|---|---|
| `transform/ipm.ts` (new, shared) | The 16 IPM tables (4 per-session, 12 result tables with their section and item reference), the staged read (QR, `created_at` in the source zone), the tenant's IPM zone, `legacyKeyOf` (`<qr>\|<day in the tenant zone>`, ≤ 64), the code maps (04 § 5, P19-01 § 5.1), `resultValuesOf` (one row's values in every section), and the header and results fingerprints |
| `transform/ipmSessions.ts` (step 11) | Imported sessions as **drafts**. The highest header wins (the rest `duplicate_header`); header-less keys from the result tables; the device by the QR's staged inventory row and `id_map` (`no_device`); the performer from the environment, else the header, else any row (person / former user / "Upstream import"; `performer_not_found`); an unknown code `value_out_of_range`; visits recomputed per device, the upstream one kept; device, facility, room and floor snapshots. Re-run: an existing key whose header matches is mapped, else `session_changed_upstream` |
| `transform/ipmResults.ts` (step 12) | Results into this transaction's drafts. Sort order is the upstream id order per section; the definition comes from the item id, else a unique label in the section. Rows are `session_not_imported` or `value_out_of_range`. Re-run: rows of an issued session are mapped when they match, else `session_changed_upstream`. **Then the issue of every imported draft:** a report number per facility and day after the highest, a 192-bit token, the issuer, and the `ipm-report-v1` hash over the stored results (ipmReport.service's `reportPayload` / `contentHash`), set by one draft → submitted UPDATE. Each issued session and each result gets its own CREATE audit row |
| `steps.ts`, `auditRows.ts` | Steps 11–12 registered (the three per-session tables moved from step 12's list to step 11's, per 05 § 3.1); `STEP_AUDITED` += `inspection_sessions`, `inspection_results` |
| Migration `0141-upstream-transform-ipm` | The reason CHECK gains `session_not_imported` and `session_changed_upstream`. Column grants: sessions SELECT (no token), INSERT (the draft columns), and UPDATE of the issue's columns only; results SELECT and INSERT; snapshot reads on `calibration_devices`, `calibration_records` and `tenants` |
| Contracts | +2 quarantine reasons (33). `openapi.json` and `schema.d.ts` are unchanged (the reasons are not in the spec; `openapi:check` and `api:types:check` are current) |
| Guards | G-14 and D-05 entries for `ipm.ts`, `ipmSessions.ts` and `ipmResults.ts`. `tenantOf` binds the tenant (`z.tenant_id = $1`) |
