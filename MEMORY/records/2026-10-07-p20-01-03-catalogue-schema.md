## What surprised me (findings → ADR-125 Amendment 2)

1. **The spec contradicted itself on DELETE.** § 7.7 replaces a draft's items wholesale *and* gives `callibrator_app` no DELETE on all six tables. Resolved: the items keep DELETE; their trigger refuses it (for every role) unless the parent is a draft.
2. **D-21 makes every DECIMAL a JavaScript number**; the spec carries limits as exact decimal strings (scaled-integer comparison, a hash over the text). The catalogue's twenty limit/range attributes are a reviewed D-21 exception, held by `decimalGetters.d21` to read as strings.
3. **D-20 wants every foreign key to lead an index**, so the spec's `(tenant_id, device_type_id)` became `(device_type_id, tenant_id)`.
4. **Sequelize replacements and `::` casts** were never used together in a migration here; the seed uses `CAST(:x AS type)` to be safe.
5. **The am3 upgrade suite's seed rows assumed base ce74932**: a base after 0096 needs a certificate's verification token. The seed now adds one when the column exists (`upgradeBoot.am3.live`), so the suite runs from any later base.
