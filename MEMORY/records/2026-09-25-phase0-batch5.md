## How It Ran

Up to **twenty** agents worked concurrently on one working tree, then the owner lowered the limit to four
and let them finish. Every agent proved fail-before in a separate `git worktree` at the baseline and removed it.
Migrations with real SQL were run on throwaway `pgvector/pgvector:pg18` (PostgreSQL 18.6) containers.

Coordination failures, and how each was caught:
- **Two migrations numbered 0039.** The orchestrator assigned 0039 without knowing A-170 would need
  one; the A-126 agent's became **0049**.
- **The A-176 allow-list would have broken A-160's MFA policy.** Both agents were told before either finished.
- **Deleting the retention-policy model broke the A-88 FK test.** Its owner was told and fixed it.
- **A boot failure on every existing database** (below). It was found by two agents' PG18 runs and
  fixed by the orchestrator before commit.

## The Boot Defect Fixed at Commit

`signatureWorkflow.model.js` declared an index on `requested_by`. Boot runs `sync()` **before** the
migrations, and on any database created before `0039` the column does not exist yet, so `sync()` failed
with `column "requested_by" does not exist` and the backend never started. The index is now created only
by `0039`, which handles both fresh and existing databases.

**Stated carefully:** the fix follows from the code, since `sync()` without `alter` touches no other column,
but the upgrade path from 05985ef has **not** been re-run on PG18 after it. This deploy wipes the database,
so it exercises only the fresh path.

## Before Deploying — Read This

- **Migrations `0035`–`0044`, `0047` and `0049` run at boot.** On an existing database, `0037` refuses
  NULLs in NOT NULL targets and dangling signer or revoker ids, so run its orphan check (its header) first.
  `0047` refuses if `data_retention_policies` has rows.
- **VM `.env`:**
  - `CLAMAV_ENABLED=true` with `CLAMAV_HOST`/`CLAMAV_PORT`, or every upload is refused 422.
  - `LOG_TO_FILE=true` if `log/activity/*` files are still wanted; production now logs JSON to stdout.
- **Webhook receivers must switch** to the `v1=` HMAC over `timestamp.body` (ADR-054); there is no dual-signature period.
- **Rotate** any secret that ever sat in `tenants.settings`, and **flush** `tenant:*`, `tenants:*` and
  `permissions:*` (a new menu, `ai-assistant`, and the A-07 slug changes).
- **Behaviour users will notice:**
  - `PATCH /tenants/settings` refuses unknown keys.
  - `anonymizeDataset` is refused.
  - A tenant can require MFA.
  - Accounts created by an admin that never signed in must change their password.
  - Expired workflows cannot be edited.
  - Search fails loudly instead of showing "No results".
