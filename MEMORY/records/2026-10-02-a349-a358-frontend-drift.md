## Rule applied
The backend (route → service → `.openapi.ts` contract) is the source of truth. Where a screen showed a field the API never answers, the screen was changed: either it reads the field the API does send, or the UI for the missing field was removed. Each case was checked in `backend/src`. Showing the missing data would have needed a backend change in two cases (A-351, A-356), and here the data does exist server-side. Those two are reported below, not built. No file under `frontend/src/services/` or `frontend/src/api/` was edited; that is the service-migration lane.

## Decisions (made under the owner's delegation, best practice)
- **A-351 code badge, A-356 suspension fields: removed, not wired.** The data exists in the database (`kanban_projects.code`; `tenants.suspension_reason` / `suspended_at`) and both are plainly meant to be shown, but neither read returns them. Showing them means adding the fields to `listProjects` + `KanbanProjectSummary`, and to `getTenantLifecycleStatus` + its contract. Both are backend changes, out of this card's scope. Removing the UI is no regression, because neither field ever rendered. **Follow-up for the backlog:** decide whether to expose them. For A-356 the alternative is a second read, `GET /tenants/:id`, but it sits behind a different gate than `tenant-lifecycle: read`, so a tenant reader could get a 403 there.
- **A-352 sprint counts: removed, not fetched.** `GET …/sprints` does return per-sprint counts, and the backend comment says they are "for the sprint picker". Wiring them would add a second read that every card create, move or migrate (and every socket event) would have to refresh. A stale count is worse than none. Removed. Wiring it with a refresh is a feature for a later card.
- **A-353:** the page does not call the tenant read without a tenant. It does not ask the backend to accept a missing `tenantId`.

## Left for the service-migration lane (`frontend/src/api/services/`, not edited here)
- `featureFlag.service.ts#getTenantFlags(tenantId?: string)` still has its commented `tenantId as string` cast. The page now always passes a string, so the parameter can become required and the cast can go.

- `tenantLifecycle.service.ts`: `TenantLifecycleStatus` still adds `suspensionReason?` / `suspendedAt?`. No reader is left, so the widening can go.
