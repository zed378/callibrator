## One harness trap found while taking it

A first attempt set `E2E_MFA_STATE_FILE` to a single scratch file. `setup.js` then shares **one**
state file across every identifier, so a spec signing in as a user it just created was handed the
seeded operator's cached session; `/auth/just-update-password` answered 400 and `auth`, `http` and
`sop` failed (41 tests). That run is **void** — the stack was destroyed and rebuilt, and A and B used
the default (one state file per identifier in the OS temp directory). `E2E_MFA_STATE_FILE` is only
safe when a run signs in as one identifier; noted in ADR-092.
