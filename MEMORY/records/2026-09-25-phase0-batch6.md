## How It Ran

At most **eight** agents ran concurrently on one working tree. As each finished, another took its slot:
wf, auth, tenant, files, data, guard, infra, fe, then async, dbA, dbB. Agents did not edit the boards,
ADRs or records; the orchestrator wrote those from each agent's report.

**Environment finding.** The container's system Node is 22. On Node 22 the otplib/@scure suites fail
with "Must use import to load ES Module", which left the baseline apparently red: 8 suites. On
**Node 24.21**, the version the project targets, the same suites pass (128/128 tests). CI must pin
Node 24.

**Fail-before** was shown against `fabc3be`, the last commit before batch 6, in throwaway worktrees.
A mid-batch checkpoint commit already carried part of the agents' work, so it could not serve as the
baseline.
