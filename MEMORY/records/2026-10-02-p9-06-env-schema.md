## The rules are the existing ones
Every rule restates a refusal that already ran as its module loaded:

| Module | Rule |
|---|---|
| `config/index.ts#validateConfig` | DB vars set and not blank, `DB_PORT` 1–65535 by `parseInt`, `DB_DIALECT` postgres |
| `utils/jwt.util.ts` | both secrets set and different (A-31); `JWT_ALGORITHM` one of the pinned nine |
| `certificateDocument.service#requireSigningSecret` | `CERT_SIGNING_SECRET` set |
| `kms.service` | production needs `KMS_MASTER_KEY`; any set key, current or previous, must be 32 bytes |
| `config/publicAccess#assertPublicAccessConfig` | production needs `ACCESS_REQUEST_IP_PEPPER` |
| `config/billing#stripeSecretKey` | production with billing enabled needs `STRIPE_SECRET_KEY` (ADR-111; billing as defined there) |

Requiring `ENCRYPT_KEY` (read only by migration 0058), `HOST_URL`/`PUBLIC_BASE_URL`, `PRIVACY_NOTICE_URL` or `FORCE_HTTPS` would refuse a configuration that boots today, so none of them is in the schema.

## Evidence
- **Identity of verdicts:** `environmentSchema.p906` "over the configuration matrix" runs 158 configurations (a valid base and 38 single changes, plus 40 seeded combinations, in development and in production). For each, it loads every checking module for real in an isolated registry and compares the set of modules that refuse with the schema's set: **0 mismatches**. Both sides are exercised: more than 50 configurations refuse and more than 10 boot.
- **Plants (scratch mirror):** dropping the production KMS rule fails 2 of 4 tests; adding an `ENCRYPT_KEY` requirement fails 4 of 4.
- **Real boot, valid environment:** PG18 18.6 and Redis 8 (named `p906-pg`, `p906-redis`), from `dist/`.
  - It reaches "Server running"; `/live` answers 200.
  - `/health` answers 503 because the optional dependencies are absent; it does so with and without the check.
  - The same boot without the new call (a scratch copy of `dist/index.js` minus that line) gives the **same log as a multiset**: 283 lines, timestamps and timings masked, cut at the first dispatcher tick.
- **Real boot, broken production environment:**
  - Old: stops at the first module's check (the JWT rule) and prints it only as a winston JSON exception record.
  - New: exit 1, one error on stderr listing **all 8** problems (`DB_NAME`, `DB_PASS`, `DB_PORT`, `JWT_REFRESH_SECRET`, `CERT_SIGNING_SECRET`, `KMS_MASTER_KEY`, `ACCESS_REQUEST_IP_PEPPER`, `STRIPE_SECRET_KEY`).
  - The message contains no secret values.
- **Docs cannot drift:** a test requires every schema variable to appear in `.env.example` and `docs/BACKEND/11`. Four (`JWT_ALGORITHM`, `KMS_MASTER_KEY_PREVIOUS`, `ACCESS_REQUEST_IP_PEPPER` in the doc, `BILLING_ENABLED` in the doc) were missing before this change.
- **Gates:**
  - `load:check` passes in dist (a production child) and src.
  - Full backend suite: 864 passed, 0 failed.
  - Lint 0/0, ratchet at the floor.
  - typecheck and build:dist are red only on other lanes' in-flight files (`supplierScorecard.route.ts`, `storage.openapi.ts`).
- **Cleanup:** both containers and the pulled `redis:8-alpine` image were removed by name.
