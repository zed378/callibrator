## P7-03 evidence

- **Harness** (scratch):
  - the repository's `deploy/observability/docker-compose.logging.yml`, unchanged in effect, as compose project `p7obs`;
  - an override that adds `grafana/loki:3.5.5` on `127.0.0.1:19310` and a second Vector config with a `file` sink over the same `route` outputs;
  - Vector is the pinned `timberio/vector:0.58.0-alpine@sha256:5dcf67db…`, with `read_only`, `cap_drop: [ALL]` and a read-only socket.
- **Source:** a real backend container, `p7obs-backend`: `node --import tsx index.js`, `NODE_ENV=production`, `LOG_TO_FILE=false`, on the migrated PostgreSQL 18 above. It carries the labels `com.docker.compose.project=callibrator` and `com.docker.compose.service=backend`, which the template's `include_labels` selects.
- **Traffic:**
  - `GET /api/v1/tenants?access_token=SEKRET-QUERY-TOKEN-123&page=1`, sent with a Bearer JWT;
  - `POST /api/v1/auth/login` with `password` in the body;
  - `GET /api/v1/nope?password=SEKRET-PW-IN-URL`;
  - a second labelled container, `p7obs-noise`, printing a JSON line the application never redacted (`password`, `Bearer abc.SEKRET…`, a JWT) and a text line with `Basic SEKRET…`.
- **Result, file sink:** every backend line arrived as parsed JSON (`structured: true`, `service: backend`). Each `request completed` line carried the `requestId` that the response header `X-Request-Id` returned (`0765e55a-…`, `d9d63a12-…`, `8f528c73-…`, and on the second run `77747009-…`). The URLs arrived as `?access_token=[REDACTED]&page=1` and `?password=[REDACTED]`. Vector redacted the noise line: `password: [REDACTED]`, `Bearer [REDACTED]`, `jwt: [REDACTED]` and `Basic [REDACTED]`. **`grep -c SEKRET shipped.ndjson` → 0**.
- **Result, Loki:**
  - the labels are `level`, `service` and `service_name`;
  - 4 streams;
  - `SEKRET in loki: 0`;
  - 5 of 6 lines have `requestId`; the sixth is the text line;
  - after the fix, `{alert=~".+"}` returns `job.retention-sweep.not-scheduled`.
- **Defect found and fixed:** the one Loki sink templated `labels.alert = "{{ alert.key }}"`, and on every non-alert event Vector logged `template_failed … Missing fields on event: ["alert.key"]`. It now uses two sinks, `loki` and `loki_alerts`. `vector validate --no-environment` passes, and the second run logged 0 `template_failed`.
- **Also seen:** the Loki sink's startup healthcheck failed once with 503 while Loki was still starting. Vector continued and shipped.
- **Also seen:** a client-supplied `X-Request-Id` is not honoured; the server assigns its own. This is by design, and noted only because it shapes how a client correlates.
