## What the Halted Work Turned Out to Be

**Most of the 53 failures were stale or platform-bound tests, not broken code.**
- **Windows path separators:** D-05, D-17.
- **A parse error in a test's own sample:** D-18.
- **Test doubles missing `assertQueue`:** since W-09.
- **Tests encoding contracts deliberately changed:**
  - A-256 removed custom-domain TLS;
  - W-07 and W-08 changed the batch-job claim, with no fake handler;
  - W-09 moved email retry into broker delay queues.
- **A node-cron mock without `validate`.**
- **Symlinks without the privilege:** on Windows.

Each agent stated for each suite whether the code or the test was wrong.

**Real code defects were found and fixed along the way:**

| | |
|---|---|
| **W-33: every bulk delete in a tenant context failed** | Sequelize maps attribute names to columns *before* `beforeBulkDestroy`, so the hook's `tenantId` reached SQL. **Five tenant-user routes answered 500:** deleting a kanban project; deleting one, several or all notifications; and resetting storage settings. The route list is proven by a live test that fails on `beb0c4b`'s hook and passes now |
| **W-34: `sum`, `max`, `increment` and `restore` ran no tenant hook** | inside tenant A, `Stock.sum` returned **1107**, A's 7 plus B's 1100, on PG18. These statics are now wrapped on every tenant-scoped model; a truncate in a tenant context is refused |
| **W-30** | the scheduled calibration scan passed no actor, so every work order it created rolled back |
| **W-32** | the IoT anomaly alert wrote `type:"system"` against an enum of `SYSTEM`: no anomaly alert had ever been stored |
| **W-31** | the batch worker acked messages on the wrong channel |
| **CI would have been red on its first run** | actionlint failed the workflow itself; gitleaks flagged the repo's own placeholder; the frontend stage never ran coverage |
| **A-259** | since P6-03 the backend runs as `callibrator_app`, so demo unseed died part-way on append-only records. It is now one transaction that refuses first. `syncTables`, `resetAndSeed` and `dropSeededTables` are removed |
| **A-116** | a global `uuid` mock gave every model the same id in unit runs. It is removed; Sequelize now gets the real module |

## Before Deploying — Read This

- **Migration `0078` runs at boot.** On an existing database it gives accounts that must change password a 72-hour window from the upgrade. This deploy wipes the database.
- **The VM `.env` needs:**
  - a Redis password (S-09, `requirepass`);
  - URL-safe `RABBITMQ_USER` / `RABBITMQ_PASS`: the URL is built from them;
  - `CLAMAV_ENABLED=true`.
- **`DB_APP_ROLE` defaults to `callibrator_app`:** queries run as the application role after migrations.
- **After deploy, the operator must enrol MFA** before any super-admin action (P6-07, batch 6). The E2E harness has never run against a live server.
- **Every page now renders per request** (ADR-071), so there is no prerendered HTML.
