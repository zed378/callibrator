# 2026-09-30 — P10-09: forgot and reset password

**Card:** P10-09 · **ADR:** ADR-098 · **Status:** DONE in code

## Built

- `app/forgot-password/page.tsx` (server, `AuthShell`) and `components/ForgotPasswordForm.tsx` over the OTP flow the backend always had (`POST /auth/send-otp`, `POST /auth/reset-password`).
- Step 1: *Email* (`autocomplete="email"`) → **Kirim kode**. The page shows the same sentence whatever the backend knows: *Jika email terdaftar, kami telah mengirim kode 6 digit. Kode berlaku 5 menit.* Any refusal other than 429 or network is treated as "sent", so the page cannot become an oracle even if the backend answered differently.
- A 429 from ADR-100's budget: the wait (minutes from `retryAfter`/`Retry-After`) and a resend cooldown counting down from `Retry-After` (60 s by default after a send).
- Step 2: *Kode* (`one-time-code`, digits only, spaces stripped), *Kata sandi baru* (`new-password`, show toggle), the rule the reset schema enforces stated under the field before typing (`backend/src/validators/auth.validator.ts` `password`: 8–100, upper, lower, digit), checked before the request. A refused reset is ONE sentence that does not say whether the code or the email was wrong. Success → `/login?status=reset`, where a `role="status"` notice says the password was updated.

## Evidence

- `frontend/src/app/forgot-password/__tests__/forgotPassword.p1009.test.tsx` — 7 tests: labelled, `autocomplete="email"`, axe clean; a known address, an unknown address and a 403 all get the same neutral sentence and the code step (`one-time-code`, `new-password`, `aria-describedby="reset-rule"`), axe clean; a 429 shows "Try again in 2 minutes." and a disabled "Resend the code in 120 seconds"; a refused reset shows the generic sentence (never "Invalid OTP"), then success posts `{email, otp: "222222", password}` and goes to `/login?status=reset`; a rule-breaking password never reaches the API.
