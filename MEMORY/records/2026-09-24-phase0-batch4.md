## The Owner Questions

The owner directed that contradictions be settled by agents debating from opposite positions, with
the orchestrator deciding. Two papers argued Q-09 to Q-19 independently: one compliance-first, one
for operability. They agreed on more than half. ADR-051 records every decision and which side it
took, and why.

**Both papers found live defects while reading the code.** Two were checked and confirmed before
deciding:
- **Workflow signing refused every real user:** `"active"` against a stored `"ACTIVE"`, with seven
  test files encoding the lowercase fixture (A-119).
- **Admin-created users were stored unverified** (F-2).

## The Headlines

| | |
|---|---|
| **Audit rows are permanent** | every purge path is removed (A-121); `audit_logs.tenant_id` is `RESTRICT` (A-122, W-20); deleting a tenant with audit rows is now **refused on PostgreSQL 18.6**, where before it deleted them |

## Not Covered — Read Before Deploying

**Migrations `0028`, `0029` and `0030` run at boot.** `0030` **refuses** if orphan rows exist, so run
its orphan check by hand first. `0028` and `0029` have not yet run on real PostgreSQL. Check
`\d users` and `\d audit_logs`.

**Deploy steps:**

1. **Recreate the network.** A full `down` and `up` is needed for the pinned subnet (ADR-050).
2. **Flush `permissions:*` in Redis.** New slugs and grants: `esignature` and `profile-page`.
3. **Verify, in order:**
   1. a real sign-in records a real public IP, not the gateway;
   2. **MFA setup works in the deployed pkg binary** (the otplib ES-module dependencies);
   3. **only then** set `AUTH_RATE_LIMIT_BY_IP=true`.

**Behaviour changes users will notice:**
- USER, ROOM USER and WAREHOUSE STAFF lose signing (ADR-051 Q-19). The migration is still to write.
- Technicians lose QMS.
- Every admin-created account will be forced to change password, once A-123 lands.
